# CCAP 百萬行專案冷啟動策略 (Zero-Token Cold Start Strategy)

**版本**: V1.0
**目標**: 解決超大型專案 (1M+ Lines) 在初始化階段對 Token 的毀滅性消耗，實現「本地編譯、語義壓縮、按需閃回」。

---

## 1. 本地語義編譯器 (Local Semantic Compiler)
拒絕讓 LLM 參與原始碼的「掃描、分類與整理」過程。這段工作應由本地高效能引擎（C++/Rust/Python）在 0 Token 成本下完成。

### 1.1 結構採集 (Structural Harvesting)
*   **技術**: 使用 **Tree-sitter** 或 **LSP (Language Server Protocol)**。
*   **特性**: 100% 準確的 AST (抽象語法樹) 提取，具備類型感知與定義跳轉能力。
*   **成本**: 消耗本地 CPU，Token 成本為 0。

### 1.2 向量映射函數 $f(AST) \rightarrow \vec{v}_m$
*   在本地將 AST 轉換為特徵張量。
*   **正規化**: 透過 SVD (奇異值分解) 消除特徵間的共線性，確保產出的特徵向量在數學上趨近正交。

---

## 2. 資訊熵分層與圖塌陷 (Entropy-based Graph Collapsing)
針對百萬行代碼進行「有損但結構保真」的降維處理。

### 2.1 區域塌陷 (Area Collapsing)
*   **低熵區域**: 重複性高的 DTO、Boilerplate、Getter/Setter。本地引擎自動將其合併（Collapse）為單一節點，僅保留類型定義資訊。
*   **高熵區域**: 包含複雜演算法、加解密邏輯、核心業務流的模組。保留更高維度的特徵描述。

### 2.2 拓樸骨架生成 (Topological Skeleton)
*   將整個專案編譯成一份約 **100KB 的 AAAK-Math 拓樸圖**。
*   此地圖僅包含「模組節點」與「高權重依賴邊界」。

---

## 3. 按需閃回機制 (On-demand Flashback Protocol)
AI 在對話過程中始終保持「輕量化」狀態，僅在關鍵時刻獲取細節。

1.  **全局認知**: AI 啟動時僅讀取 100KB 的拓樸骨架（約 2,000 Tokens）。
2.  **路徑尋優**: AI 透過數學導航鎖定受影響的模組座標。
3.  **精確解壓**: 當 AI 下達修改或診斷指令時，工具才「即時」讀取目標檔案的原始碼。
4.  **優勢**: AI 雖然只讀了 1% 的原始碼，但因為有拓樸骨架的指引，它對這 1% 代碼在整個系統中的「戰略位置」有著 100% 的準確認知。

---

## 4. 預期效能 Benchmark
*   **初始化 Token**: 0
*   **會話啟動 Token**: < 2,500 (骨架 + 任務上下文)
*   **幻覺率**: 趨近於 0 (因為結構資訊來自確定性的靜態分析)
